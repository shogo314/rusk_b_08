# β08: 多次元入力に必要なネイティブ引数展開の案

これは未実装の設計案。Tuple入力は既存のフィールド展開へ移したが、多次元配列入力の本体と`$fn`置換はまだ`containers.rs::read_function`にある。

## 選ぶ方向

入力の次元列をRuskのTupleへ詰める案は、入力ごとに形状オブジェクトを確保すると、短い配列を繰り返し読む場合に追加コストを生む。現在の値渡しの引数列を保ち、externの明示した参照記法から実際の関数の引数型・番号を列挙する小さな試作を先に行う。

Rusk関数に可変長引数や型パックを追加する案ではない。通常の固定個数の引数を持つexternでも使える、本体テンプレートの展開として扱う。C++の任意の字句を置換せず、明示した範囲だけを展開する。

## 最小の参照記法の候補

- `@{arguments as P,I}`から`@{end}`までを、その関数の引数の宣言順に展開する。Pは論理型、Iは既存の番号参照で扱う。`from 1`等で先頭を除いた列も参照する。
- 型付きの`call`・`boxed_call`の引数型列に、実際の引数型列の末尾を展開する記法を用意する。例えば`boxed_call __read__(...arguments 1)->T`を検討する。
- C++の仮引数と実引数は、本体が明示する名前と番号で組み立てる。末尾のLocの前に各項目とコンマを出す形なら、独立したコンマ判定命令を追加せずに済む。
- 束縛はフィールド・variantと同じ局所的な規則を使う。展開の深さ・作業量、添字の範囲、未使用宣言の検査も共通化する。

この記法は候補であり、まだ利用できない。具体構文と未使用の宣言で検査できる範囲は試作で決める。

## 標準の多次元入力へ接続する方法

標準の本体を役割で登録し、入力構文が要求した実際の引数列と返却型へ接続する。返却型のパターンを通常の型引数の照合で具体化し、子の配列型・入力操作の名前をコンパイラのC++本体へ埋め込まない。

本体は全次元の負数を先に検査し、外側の長さを一度取得する。要素は型付きの入力参照と末尾の次元引数で読む。配列の最大長・予約・要素格納は標準本体へ移す。元の次元変数を利用者readerが変更した場合に、今回の行と後続の行が観測する値も従来と比較する。

利用者が定義した元の個数の引数を持つreaderを先に選び、各階層の子readerも通常の候補から解決する。Unitは格納用のオブジェクトABIを使う。既存の一次元入力と、利用者による別名のexternも同じ参照を利用できることを確認する。

## 試作で確認すること

1. 0・1・複数の引数、途中からの展開、束縛と不正な添字、入れ子と展開量の上限。
2. 論理型が異なりC++型が等しい引数、型付き呼び出し・Unitの両ABI・効果と保持の依存。
3. 多次元入力の順序、途中EOF、外側が空で内側が負数の場合、利用者readerの優先と次元の変更。
4. 一次元と多次元の確保数・共有コピー数・時間をβ07と比較し、引数列の移行で新しい確保を増やさないこと。

試作が成立したら多次元入力のC++本体生成と`$fn`置換を削除する。成立していない段階で、これを移行済みやコンパイラにしか書けない例外とはしない。
