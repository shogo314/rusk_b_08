# Rusk の設計ノート

Rusk の目的、設計を判断する基準、対話で合意した方針と未決定の問いを記録する。利用者向けの言語ドキュメントや完成した仕様書ではなく、設計を進めるための道しるべとする。

β08はfixしたβ07を引き継ぎ、externを含む通常のライブラリ定義の汎用化とコンパイラ内の専用処理の削減を進める。[β08の要件](beta08.md)を参照。

## 読み方と記録の状態

- 決定した方針は「〜とする」「〜を使う」と記す。今後の具体例で見直すことはできる。
- 「案」「検討中」「候補」は、まだ採用していない選択肢。
- 「未決定」「保留」は、後で判断する問い。提案を自動的に決定扱いにしない。
- コード例は設計の説明用で、未確定の型名や構文も含む。`Int/int`、真偽値リテラル、ジェネリクスなどの表記は確定済みとは限らない。

β03で合意した要件・完成条件・実装順序は [β03の計画](beta03.md) に記録する。

β04の合意した範囲は [β04の要件](beta04.md) に記録する。

β05の合意した範囲は [β05の要件](beta05.md) に記録する。Option・不在演算子・比較の連鎖・辞書と集合の初期仕様はこの要件を優先する。

β05で追加する処理系の分離は [変換段階の構造](pipeline.md) に記録する。

ブロック式とラベルの追加合意は [ブロック式とラベル付きループ](blocks-labels.md) に記録する。

## 現在の検討状況

ジェネリック処理の名前解決は再検討中。mixin、暗黙の静的引数、トレイトは候補として比較し、最終採用は未決定とする。β02では型・名前付き関数をトップレベルに限定した具体化を実装し、グローバルの関数群で名前を解決する。言語全体のローカル関数・名前解決の最終方針とは分ける。

合意した設計方針は、すべてを最初から実装する約束ではない。β02の実装範囲と完成条件は [β02の計画](beta02.md) に記録する。

[整理の確認と未解決事項](review.md) に、今回確認した記録の更新漏れと、仕様を組み合わせる際の未解決事項をまとめる。

## 主な未決定事項

- C++ と LLVM IR の採用範囲。
- オブジェクトの寿命管理方式、捕捉環境の実装方式と再帰・既定値との関係。
- 読むだけの制限の型表現と検査方法。
- 一時オブジェクトへの代入の可否、代入式の詳細な構文。
- 高速化を意識した配列の仕様、スライスの使用中の範囲、構造変更の検出。
- readonly、動的関数型への拡張。汎用enum/match・Option・`??`・`?!`はβ05、無名関数はβ04で具体化。
- ジェネリクス、コンパイル時の値、型推論の範囲と書き方。
- 型名と真偽値リテラルの表記、未確定の入力・書式 API。

この一覧は主要な論点の入口とし、詳細と他の未決定事項は各分野の記録を参照する。
