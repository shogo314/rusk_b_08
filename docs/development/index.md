# 開発ガイド

処理系は Rust と Parol で実装し、C++20 を生成します。基本型、共有とコピー、制御構文、関数、配列・文字列操作を備えたプロトタイプです。

β08では、externを含むライブラリ定義の汎用化と、コンパイラ内の専用処理の削減を進めます。開始点と対象は[β08の実装方針](beta08.md)を参照してください。

## C++の実装をRusk側に置く

外部型・関数の宣言はトップレベルに置きます。プロパティは JSON 形式の文字列で、末尾のカンマが必要です。以下は暫定的な外部実装インターフェースです。

```text
extern type Int {
    cpp_name: "std::int64_t",
}
extern fn __add__(a: Int, b: Int) -> Int {
    cpp_name: "rusk_add_int",
    code: "Obj<std::int64_t> rusk_add_int(Obj<std::int64_t> a, Obj<std::int64_t> b, Loc loc) { return make_obj<std::int64_t>(checked_int(static_cast<__int128>(*a) + *b, loc)); }",
}
```

これは標準ライブラリから抜粋した例で、利用プログラムに再定義する必要はありません。`extern symbol 名前 { code: "...", }` は共通コードを出力します。すべてのsymbolと、必要になった外部関数のコードを出力します。symbol間は名前順です。外部関数間の依存は型付きの関数参照で登録でき、前方参照と相互再帰にも対応します。ジェネリックexternと参照記法は[β08の試作](beta08-extern-prototype.md)を参照してください。

ABI は引数と戻り値を `Obj<T>`（現在は `std::shared_ptr<T>`）で渡し、末尾にエラー位置の `Loc` を受け取ります。戻り型省略時は C++側を `void` にします。外部関数には正しい C++ と共有・コピーの契約を守る責任があります。

関数は名前と引数型で選び、具体的な宣言とジェネリック宣言を共通の候補表で解決します。ジェネリックの型引数は引数と期待される戻り型から補えますが、期待型だけで複数の適用可能な候補を選ぶことはしません。具体的な戻り型による選択は `in` のための `__read__` と配列構築用の内部フックに限ります。外部宣言自体は先に登録するため、ソース上の使用箇所より後にも書けます。

宣言の `let x = value;` は、宣言型の文脈を使って右辺を検査してから通常の `copy` の候補解決へつなげます。`let x := value;` はコピーせず共有します。これにより、型注釈付きの空配列をコピーして宣言する場合も型の文脈を保持します。

## 暫定実装と設計の区別

共有ポインターは意味論の検証用です。基本型の一時結果は実体化を遅らせ、閉じたスカラーの別名群には値保持も使います。共有が外へ出る値やコンテナへの格納では共有オブジェクトを保持します。通常のRusk関数には、解析結果に基づく引数借用も適用します。[β07の実装と検証](beta07.md)を参照してください。限られた性能測定の改善だけで言語全体の速度目標を達成したとは扱いません。整数の検査は GCC/Clang の `__int128` を使います。

β05では[HIRとLIRを経由する構造](pipeline.md)へ移行しています。型・参照先を解決したHIRから、制御フローを基本ブロックとジャンプへ落としたLIRを作り、その後にC++を生成します。β03の一時値の確保削減とバッファ入出力は維持しています。LLVM、内側の名前付き関数、高度なジェネリクスは未実装です。

設計の思想・理由・保留事項は `design/`、実装済みの説明は `docs/` に残します。ドキュメントの編集方法は [編集と公開](documentation.md) を参照してください。


## 配列の初期実装

`Vec<T>` は、基本型または別の配列を要素型としてコンパイラが具体化します。型引数を持つユーザー定義型も具体化し、構造体やタプルを要素型にできます。長さ・添字・コピー・代入・反復などの基本18操作と、配列反復型`Iter<Vec<T>>`は、preludeで読み込む`lib/vec.rusk`の通常のジェネリックexternです。入力・出力・比較・順序付けの13操作は、型が初めて必要になった時点で`lib/vec_compat.rusk`の署名に型引数を束縛し、明示したC++型・関数参照を展開して登録します。Vec型の専用登録、要素型の制限と操作の選別は、β08で引き続き移行する対象です。

格納形式は `RuskVec<T>`（`std::vector<Obj<T>>` に変更回数を追加した型）です。再確保後も取得済みの要素への共有は有効です。コピーと `=` は要素を再帰的にコピーし、連結と `sorted` は要素を共有します。

空配列の型は宣言・代入・関数引数の文脈から求めます。関数引数では引数数と先に確定した引数型で候補を絞り、残った候補が要求する型が一致するときだけ使います。後続の引数や文からの推論は行いません。

`for` は `__iter__`、`__iter_has_next__`、`__iter_next__` へ展開します。配列のイテレータは元の配列を保持し、変更回数を検査します。範囲のイテレータは整数値を保持します。文字列の添字は、所有文字列を保持する文字の共有と、長さ変更の検査を組み合わせます。

式の一時値は文末に明示的に解放し、条件の計算に必要だった一時値は分岐やループ本体の前に解放します。これにより一時的な文字参照が不必要に長さ変更を妨げることを防ぎます。

## Ruskの関数

トップレベルの `fn` は、外部関数と共通の候補表に名前・引数型・戻り型を先に登録します。その後、関数ごとに独立した変数スコープで本体を検査して C++ を生成し、最後にトップレベルの実行文を `main` にします。名前付き関数の本体からトップレベルの変数を捕捉する処理は行いません。β04の無名関数には捕捉環境を作ります。

C++側では各Rusk関数に固有名を付け、全関数の前方宣言を出します。これにより定義前の呼び出しと相互再帰に対応します。共有ABIは引数と戻り値に`Obj<T>`を使い、`Unit`の戻り型は`void`です。最適化時は、本体から更新・構造変更・脱出がNo、外部書き込みもNoと証明できた引数を`const Obj<T>&`で受け取ります。外部関数のABIは変更しません。引数の結び直しは関数内の共有ポインターだけに作用します。

型引数を持たないRusk関数は未使用でも本体を検査・出力します。ジェネリック関数は呼び出された型引数の組ごとに具体化して検査・出力します。外部関数はトップレベルの実行文またはRusk関数本体から参照したものを出力します。未使用のRusk関数から参照した外部関数も含みます。Rusk関数の戻り値の検査は構文上の `return` と分岐に基づく保守的な解析です。ループや到達不能な文を含む一般的な制御フロー解析は今後の課題です。

## プロトタイプの完成範囲と検証

基本問題を記述・C++20へ変換・実行でき、共有とコピーの意味論、型・初期化の診断、実行時の位置付きエラーを確認できることを、このプロトタイプの対象範囲とします。言語設計全体の実装完了や、競技環境での速度目標の達成を意味しません。

`examples/prototype/` に配列合計、ソートと二分探索、グリッドBFS、再帰による剰余累乗を置いています。E2Eテストでは実行例に加え、探索とBFSを独立した実装の結果と比較します。

`examples/atcoder/` にはAtCoderの解答100問と公式サンプル279件があります。`cargo test --locked --test atcoder` ですべて、末尾に `abc240_c` などの問題IDを付けるとその問題だけ検証できます。解答ごとに一度C++をコンパイルし、各サンプルの出力を空白区切りのトークンで照合します。サンプル一致は提出・ACの確認を意味しません。問題文は収録せず、出典リンクを解答と一覧に記しています。

AOJの36問・41解答とLibrary Checkerの10解答は、verification-helperで公開テストケースを取得して検証します。Ruskをカスタム言語として登録し、C++20への変換・コンパイルを接続しています。[テストの実行](verification.md) を参照してください。

```bash
python3 tools/test.py --suite sanitizers
python3 tools/benchmark.py --repeats 3 --output /tmp/rusk-benchmark.json
```

サニタイザー検証は GCC の AddressSanitizer / UBSan で文字・配列要素の寿命とBFSを確認します。LeakSanitizerが動かないptrace環境では `--no-leaks` を指定できます。ベンチマークは同じ入力についてRuskと手書きC++、利用可能ならPyPyの出力を照合し、コンパイルを除いた実行時間の中央値と環境情報をJSONで出します。速度の合否判定には使いません。`--baseline-compiler PATH` で以前の処理系とも比較できます。[β02の性能確認](beta02-performance.md) にβ01との測定結果を記録しています。

未実装の主な機能は、浮動小数点、再帰型、整列した辞書・集合、スライス、内側の名前付き関数、高度なジェネリクス、名前空間を持つモジュール、さらなる最適化です。

β02の具体化・型の制限は [β02の型とライブラリ分割](../reference/beta02.md)、開発目標はリポジトリの `design/beta02.md` に記録しています。

β04の捕捉環境・静的な呼び出し・遅延イテレータの実装、追加した検証と性能上の負担は [β04の実装と検証](beta04.md) にまとめています。
