# 最小・最大演算子

β06では`<?`・`>?`・`<?=`・`>?=`を使えます。

| 式 | 既定の動作 | 結果 |
|---|---|---|
| `a <? b` | 小さい側をコピーする | 独立した値 |
| `a >? b` | 大きい側をコピーする | 独立した値 |
| `a <?= b` | `b < a`の場合だけ`a = b`で更新する | 更新先を共有する値 |
| `a >?= b` | `a < b`の場合だけ`a = b`で更新する | 更新先を共有する値 |

```rusk
let best := 100;
let alias := best;
best <?= 7 + 3;
best >?= 4;
wt best, alias, 8 <? 4 >? 6;
```

出力は`10 10 6`です。更新は`:=`による結び直しではないため、`alias`にも変更が見えます。複合代入の結果も更新先を共有するので、`let held := (best <?= candidate);`の`held`は`best`と同じ値を共有します。

## 比較とコピー

既定の実装は同じ型の二つの値を受け取ります。通常の演算子には`<`と`copy`、更新には`<`と`=`が必要です。`<`の結果にはBoolを要求します。Int、Char、Str、比較可能なタプル・配列や、比較フックを持つ構造体などに使えます。Boolなど、標準で`<`を提供しない型には自動的な順序を追加しません。

通常の`<?`・`>?`は選んだ側を`copy`でコピーします。既存の変数やフィールドを共有して返す演算子ではありません。どちらも同値なら左側を選びます。更新の比較が偽なら代入をせず、既存のpayloadや要素への共有を維持します。比較が真なら、既存の`=`と同じく右辺のスナップショットをコピーして更新します。

```rusk
struct Entry { rank:Int; data:Vec<Int>; }
fn __lt__(a:Entry, b:Entry) -> Bool { return a.rank < b.rank; }
let entry := Entry { rank:1, data:[10] };
let held := entry.data;
entry <?= Entry { rank:2, data:[20] };
held[0] = 11;
wt entry.data;
let detached := entry <? Entry { rank:1, data:[30] };
detached.data[0] = 99;
wt entry.data, detached.data;
```

出力は`11`、`11 99`です。最初の更新は不要なので共有を保ち、同順位の通常の最小値演算は左側の独立したコピーを作ります。

## 優先順位・結合・評価順

`<?`と`>?`は同じ優先順位で左結合です。加減算より弱く、比較より強く結合します。`<?=`と`>?=`は他の代入演算子と同じ優先順位で右結合です。

```rusk
wt 10 <? 3 + 4;       // 10 <? (3 + 4) → 7
wt 8 <? 4 >? 6;       // (8 <? 4) >? 6 → 6
wt 0 <= 8 <? 4 < 5;   // 0 <= (8 <? 4) < 5 → Yes
```

オペランドは左から右に一度ずつ評価します。短絡評価ではなく、更新が不要になる場合も右辺は評価します。更新先が`rows[f()][g()]`なら、行と添字を含めて一度だけ評価・保持してから右辺を評価します。右辺が行や変数を結び直しても、保持済みの更新先を使います。

先に保持した値は共有オブジェクトです。右辺がその中身を更新した場合、比較には更新後の中身が見えます。比較フック自身の副作用も通常どおり起こります。「変更が不要なら代入しない」という規則は、比較や右辺の副作用を抑止する意味ではありません。

既存の代入先と同じく、変数・フィールド・配列や辞書の要素・文字列の文字などに使えます。未初期化変数やタプルの分解代入には使えません。

## 演算フック

| 構文 | フック | 既定の実装 |
|---|---|---|
| `a <? b` | `__min__` | `b < a`なら`copy(b)`、それ以外は`copy(a)` |
| `a >? b` | `__max__` | `a < b`なら`copy(b)`、それ以外は`copy(a)` |
| `a <?= b` | `__imin__` | `b < a`の場合だけ`a = b` |
| `a >?= b` | `__imax__` | `a < b`の場合だけ`a = b` |

標準ライブラリーに型引数付きの既定フックを定義しています。具体的な型に対する通常の関数で、それぞれをオーバーロードできます。通常の演算と更新は別のフックなので、`__min__`を変更しただけでは既定の`__imin__`は変わりません。独自の更新規則が必要なら更新フックも定義します。独自フックを定義した場合のコピー・比較・更新の動作はそのフックに従います。

既存の`min(Int, Int)`・`max(Int, Int)`関数は変更していません。演算子はそれらの名前への単純な置換ではなく、上のフックへ解決します。C++の特殊な演算子に依存せず、通常のHIRの関数呼び出しと分岐を経由します。

組み込みフックを経由する実行時エラーも、実際に演算子を書いたファイル・行・列を表示します。同じ型のフックを複数箇所から呼んでも、最初の使用箇所へ固定しません。利用者定義のフック内の操作には、通常どおりその操作の位置を使います。
